# 🎛️ Роутинг моделей в Claude Code

Гайд по настройке автоматического распределения задач. Можно повторить у себя за 6 шагов (раздел в конце).

**Идея:** умная/дорогая модель дирижирует, дешёвые/быстрые — на подхвате. Экономим квоту там, где интеллект не критичен, и бьём топ-моделью только по сложному.

**Две оси, не одна.** Выбор модели — это половина решения. Вторая половина — **effort**: он меняет глубину рассуждения и расход квоты сильнее, чем переключение между Opus и Sonnet. Глобальный `xhigh` безопасен только если у субагентов прописан свой `effort` — иначе он поедет и на grep, и на коммиты, и на доки (см. §2).

| Модель | $/1M in / out | Контекст | Роль в сетапе |
|--------|---------------|----------|----------------|
| **Fable 5** | 10 / 50 | 1M | только системная архитектура (`@architect`) |
| **Opus 5** | 5 / 25 | 1M | дефолт главного цикла и всё, чего нет в карте |
| **Opus 4.8** | 5 / 25 | 1M | пин для offensive-security (см. «Классификаторы») |
| **Sonnet 5** | 3 / 15 | 1M | research, тесты, доки, конфиги, сверка схем |
| **Haiku 4.5** | 1 / 5 | 200K | чистая механика и git-хозяйство |

## 1. Ось «модель»: тип задачи → модель

| Тип задачи | Модель |
|-----------|--------|
| Системная/межсервисная архитектура, глубокий арх-анализ | **Fable 5** (субагент `architect`) |
| Архитектура в рамках одного модуля | Opus 5 (эскалация на `@architect` — если дизайн реально сложный) |
| Сложное pure-logic проектирование (алгоритм/модель данных, без security) | Opus 5; опц. `@architect` |
| Планирование + верификация плана | черновик Sonnet 5/Opus 5 → проверка Fable (`/plan`) |
| Мозговой штурм, ТЗ/спеки, написание кода, вёрстка | Opus 5 |
| Ревью кода, ревью PR | Opus 5 |
| Security-ревью кода, дебаг, рефакторинг, performance, БД (миграции/ревью) | Opus 5 |
| **Offensive-security: pentest, CTF, аудит прод-сервера, ротация учёток, выдача и настройка SSH-доступов, ключей, прав** | **Opus 4.8** (пин) |
| DevOps/CI-CD: конфиги, пайплайны, docker | Sonnet 5 |
| API-контракты: сверка схем запросов/ответов | Sonnet 5 |
| Инцидент на проде (зависон/OOM), мета-работа (правка правил/промптов) | Opus 5 |
| Research кодовой базы, глубокий веб-ресёрч | Sonnet 5 (субагент `researcher`) |
| Тесты (TDD), прогон, обработка ошибок | Sonnet 5 |
| Документация, отчёты, суммаризация, аудит зависимостей, ревизия скиллов | Sonnet 5 |
| Механика: grep/поиск/переименования/форматирование, git-хозяйство, i18n | Haiku 4.5 (субагент `mechanic`) |
| **Всё остальное** | **Opus 5** |

**Принцип отбора:** *cheap fan-out, expensive judgment.* На Sonnet 5 уезжает то, где нет суждения — сверка схем, генерация конфигов, сбор фактов, прогон тестов. Диагностика, ревью и решения остаются на Opus 5, даже если выглядят «мелкими».

## 2. Ось «effort»

Глобальный дефолт в этом сетапе — `xhigh` (`"effortLevel": "xhigh"` в `~/.claude/settings.json`, решение 2026-07-30). Раньше здесь стоял `high` с оговоркой «не держать xhigh глобально» — она отменена: у субагентов свой `effort` во frontmatter (`mechanic` = low, `researcher` = medium), поэтому grep, переименования и research на xhigh не идут. Если у тебя субагенты без явного effort — оставляй `high`, иначе xhigh поедет и на механику.

| Уровень | Когда |
|---------|-------|
| `xhigh` | **дефолт этого сетапа**: кодинг, агентные многошаговые задачи, длинные автономные прогоны |
| `high` | безопасный дефолт, если субагенты без явного effort: диалог, ТЗ, ревью, доки, мета-работа |
| `medium` | объёмная рутина, где можно разменять интеллект на скорость |
| `low` | механика, короткие точечные правки |
| `max` | только когда корректность важнее стоимости; склонен к переобдумыванию |

Способы задать: `/effort <уровень>` в сессии · `claude --effort <уровень>` при запуске · `CLAUDE_CODE_EFFORT_LEVEL` · `"effortLevel"` в `settings.json` · `effort:` во frontmatter субагента (перебивает сессионный).

> 💡 Разовое углубление без смены сессии — слово **`ultrathink`** в промпте. «think hard», «think more» движок не распознаёт, они уходят обычным текстом.
>
> ⚠️ Шкала effort откалибрована **под каждую модель отдельно** — `medium` на Opus 5 и `medium` на Sonnet 5 это не одна и та же глубина.

## 3. Три субагента (`~/.claude/agents/*.md`)

Модель и effort зашиты в frontmatter — вызываешь субагента, он поднимается на нужной паре.

| Агент | Модель | effort | Для чего | Права |
|-------|--------|--------|----------|-------|
| `architect` | Fable 5 | `xhigh` | системная архитектура, trade-offs, стратегии миграций | read-only |
| `researcher` | Sonnet 5 | `medium` | «что где лежит и как работает», сбор фактов, зависимости | read-only |
| `mechanic` | Haiku 4.5 | `low` | grep, переименования, форматирование по чёткой инструкции | read + edit |

```markdown
---
name: architect
description: Системная и межсервисная архитектура, глубокий арх-анализ. Read-only.
model: fable
effort: xhigh
tools: Read, Grep, Glob, WebSearch, WebFetch
---
Ты — системный архитектор. ...системный промпт...
```

Frontmatter субагента принимает также `maxTurns`, `memory` (`user`/`project`/`local` — обучение между сессиями), `isolation: worktree`, `background`, `disallowedTools`, `permissionMode`.

> ⚠️ **Не ставить `CLAUDE_CODE_SUBAGENT_MODEL`** — эта переменная перебивает per-agent конфиг и снесёт `architect`=Fable.

## 4. Пины моделей на скиллах (`model:` в frontmatter)

**Принцип:** пиним только там, где модель ОТЛИЧАЕТСЯ от Opus-дефолта.

- `model: sonnet` → `docs`, `report`, `test`, `research`, `deep-research`, `dependency-optimizer`, `cicd-quick-setup`, `error-handling-standardizer`, `context-budget`, `skill-stocktake`, `api-contract-guardian`
- `model: opus` → `review` (флагман, явно)
- `model: claude-opus-4-8` → `audit-server` (обход cyber-классификаторов Opus 5)
- `model: haiku` → `fable-off`, `fable-on`
- **Без пина** (едут на дефолтном Opus 5): оркестраторы (`build`, `plan`, `spec-to-code`) и дисциплины (`systematic-debugging`, TDD, verification) — они сами дирижируют/судят
- `rules-distill` **намеренно без пина** (Opus 5), хотя соседние ревизоры `skill-stocktake` / `context-budget` на Sonnet: те считают и отчитываются, а `rules-distill` переписывает общие правила — это мета-работа, строка карты «мета-работа → Opus 5»

> Поле `effort:` во frontmatter **скиллов** документацией не подтверждено (только субагенты). Для тяжёлых скиллов поднимать effort сессии вручную.

## 5. Что харнесс делает сам — не изобретать заново

| Механизм | Что делает |
|----------|-----------|
| Алиас `best` | Fable 5 где доступна, иначе последний Opus |
| Алиас `opusplan` | Opus в plan mode → автопереключение на Sonnet для исполнения |
| **Content-fallback** | классификатор пометил запрос → Claude Code сам перезапускает на другой модели |
| `fallbackModel` / `--fallback-model` | цепочка фолбэка по **недоступности/перегрузу** (не путать с content-fallback) |
| `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` | куда резолвятся алиасы |

### Классификаторы и content-fallback

Opus 5 и Fable 5 несут классификаторы на cybersecurity и biology:

| Модель | cyber-флаг | bio-флаг |
|--------|-----------|----------|
| Fable 5 | → Opus 4.8 | → Opus 5 |
| Opus 5 | → Opus 4.8 | **refusal**, фолбэка нет |

**Фолбэк переводит на другую модель всю сессию.** Поэтому на длинных аудитах и pentest-подобных задачах не полагаться на него, а стартовать сессию явно: `/model claude-opus-4-8`. Ревью кода на уязвимости классификаторы не триггерит — оно спокойно живёт на Opus 5.

---

## 6. Фолбэк Fable → Opus (ручной, по квоте)

Content-refusal ловит харнесс. Ручные скиллы остаются как **клапан по квоте**: на Team Premium Fable упирается в 50% недельного лимита.

- `/fable-off` — переводит `architect` на Opus 5.
- `/fable-on` — возвращает на Fable.
- **Правило лимита** (глазами): использование ≥85% и >1ч до сброса → имеет смысл `/fable-off`.

## 7. Делегирование субагентам — ставить потолок

Opus 5 делегирует **охотнее** прошлых моделей (у Opus 4.8 была обратная проблема — недоделегировал). Каждый субагент заново поднимает контекст, исследует, отчитывается, а оркестратор потом читает отчёт. Без потолка это множит стоимость на ровном месте. В глобальный `CLAUDE.md` стоит положить блок вида:

- не делегировать то, что закрывается за несколько tool-call;
- не плодить ad-hoc субагентов для перепроверки своей работы — верификация в главном цикле. **Исключение:** ревью/QA-этапы, встроенные в скиллы (`/plan` шаг 3, `/build` этапы 7–9, two-stage review в `subagent-driven-development`) — это их конструкция, а не лишнее делегирование;
- одна задача → один субагент; параллельные — только под независимые крупные направления;
- не больше 20 параллельных без явной просьбы;
- делегировал — не переделывай за субагентом.

## 8. Как повторить у себя — 6 шагов

1. **Дефолт главного цикла = Opus 5** — в `~/.claude/settings.json`: `"model": "opus[1m]"` (или `/model`).
2. **Дефолт effort** — там же `"effortLevel"`. `xhigh`, если у всех субагентов задан свой `effort` во frontmatter (тогда механика уйдёт на low сама); иначе `high`, чтобы xhigh не поехал на grep и коммиты.
3. **Создать 3 файла агентов** в `~/.claude/agents/` с frontmatter `name / description / model / effort / tools` + системный промпт. Алиасы `fable` / `opus` / `sonnet` / `haiku` и полные ID (`claude-opus-5`) в поле `model` работают.
4. **Проставить `model:`** в frontmatter нужных скиллов (см. п.4).
5. **Добавить в глобальный `CLAUDE.md`** выжимку: чем полнее карта в промпте, тем дороже каждый запрос. Держать там только то, что исполняет сам агент (кого звать субагентом, где безопасный дефолт, где пин модели), а таблицы, цены и шкалу effort оставить в этом файле — он читается по необходимости, а не грузится в контекст. Блок про делегирование из п.7 — в `CLAUDE.md`, он нужен всегда.
6. *(опц.)* **statusline** — показывает текущую модель, удобно контролировать, что роутинг сработал.

> 💡 Вызов конкретной модели можно форсить и разово: у Agent-tool есть параметр `model`, он перекрывает модель агента.
